OpenCode executable
Path to the opencode binary. Leave empty to detect it automatically.
Detect OpenCode
Look for the executable on the system path and in the usual install locations.
Working directory
Directory OpenCode runs in. Leave empty to use the vault root.
Restart the runtime
Stop the OpenCode server and start it again, for example after changing providers.
Model
Default model
Model used for rewriting, in provider/model form. Leave empty to use the OpenCode default.
Load the model list
Ask OpenCode which models it exposes. OpenCode keeps the catalogue, so this is where it comes from.
Agent
OpenCode agent used for the rewrite. The build agent can read files, the plan agent cannot.
Extra system prompt
Appended to every rewrite request. Use it to set a house style or a target audience.
Allow web access
Let the model fetch web pages while rewriting. Off by default.
Providers
Provider 1
The provider id must match the id OpenCode uses, for example anthropic or openai.
Base URL
Endpoint of an OpenAI-compatible or proxy service. Leave empty for the default.
API key
Stored in OpenCode's credential store when you sync. Never sent anywhere else.
Models
Comma separated list of model ids, for example gpt-4o, gpt-4o-mini.
Sync credentials to OpenCode
Push the API keys of the providers above into OpenCode's credential store.
Publishing service
Use a publishing service
Post the packaged drafts to your own endpoint. The plugin sends nothing when this is off.
Endpoint
Full URL of the endpoint that receives the drafts.
Send test
Send a minimal payload to check that the endpoint accepts the request.

freeWrite makes no network requests on its own. It talks to the OpenCode server it starts on 127.0.0.1, and to the publishing endpoint you configure. Model requests are made by OpenCode, using the credentials stored in your own OpenCode profile.
